# 中文显示方案：自制点阵字库

## 为什么不用现成字体

| 方案 | 结论 |
|---|---|
| GFX 内置字体 | 只有 ASCII，中文显示成方块 |
| U8g2 的 wqy 字体 | GB2312 编码，设备端要先做 UTF-8→GB2312 转换，还得再带一张 20 KB 映射表 |
| LVGL + CJK 字体 | 体积从 1 MB 起步，为一个纯文本屏不值当 |
| **自制 16×16 点阵 blob** | 295 KB，查表 O(log n)，UTF-8 直读，尺寸可控 ← 选它 |

## 生成

```powershell
.\.venv\Scripts\python.exe scripts\gen_cjk_font.py            # 默认宋体
.\.venv\Scripts\python.exe scripts\gen_cjk_font.py --font simhei
```

- 字表 = ASCII 0x20–0x7E + GB2312 全可解码字符（符号区 `0xA1A1–0xA9FE` + 汉字区 `0xB0A1–0xF7FE`）
- 结果：7540 个字符，301,612 字节（295 KB）
- 字体来源优先级：宋体在 16px 下有专门的点阵化设计，笔画最清楚；雅黑/等线在小字号会糊

## 二进制格式

```text
magic   4B    "CJKF"
glyph_w u16   16
glyph_h u16   16
count   u32   字符数
records count × 40B
        ├ cp      u32    Unicode 码点（升序，供二分）
        ├ advance u8     推进宽度（像素；ASCII 是比例宽度）
        ├ pad     3B
        └ bitmap  32B    16 行 × 16 位，高位在左，MSB first
```

`count × 40 + 12 = 301,612` 字节，整块被 `board_build.embed_files` 编进 flash，
运行期符号名 `_binary_data_cjk16_bin_start` / `_binary_data_cjk16_bin_end`。

## 设备端绘制

`src/cjk.cpp`：

1. `cjk_next()` 解 UTF-8，拿到码点
2. 在记录区做二分查找（记录定长 40 B，直接算偏移）
3. 逐行取 2 字节位图，把连续置位的像素合并成 `drawFastHLine` 一次画一段
4. 光标前进 `advance` 像素

代价：一个汉字 16 行 × 最多 3 段横线 ≈ 48 次 `drawFastHLine`。
320×240 满屏 10 行 20 字（200 个汉字）约 9600 次调用，实测整屏刷新在 100 ms 量级，
正文区（每行 20 字、10 行）感觉不到延迟。

## 换字号 / 换风格

改 `scripts/gen_cjk_font.py` 里的 `SIZE`（建议 12 / 16 / 24），重新生成后重新编译。
注意 `ui.cpp` 里的行高（20 px）与每行字数（20 字）是按 16px 写的，改字号要同步调。

## 已知缺字

- 半角 `¥`（U+00A5）不在 GB2312，显示为空白；用全角 `￥`（U+FFE5）
- Emoji 一律缺字（显示为 8px 空白），票据内容用不到
- 生僻字（GB2312 以外）缺字，例如部分人名用字
