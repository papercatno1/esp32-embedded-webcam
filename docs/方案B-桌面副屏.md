# 方案 B：桌面副屏（暂存备查）

> 状态：**暂缓 —— 资料存档，等方案 A 收工后再启动**
> 定位：放在电脑旁的常驻小屏，显示时间/日历/温湿度/天气，并在"有人从身后看屏幕"时提醒。

---

## 1. 需求拆解

| # | 功能 | 可行性 | 备注 |
|---|---|---|---|
| 1 | 时间 / 日历 | ✅ 简单 | NTP 对时；断网用 RTC 或开机计时 |
| 2 | 天气 | ✅ 简单 | 和风天气 / OpenWeather 免费 key |
| 3 | 温度湿度 | ⚠️ **需外接传感器** | 板载只有 QMI8658 六轴 IMU，没有环境传感器 |
| 4 | 身后有人告警 | ⚠️ **需换实现路径** | 见 §3 |

---

## 2. 硬件补充清单

| 器件 | 型号 | 价格 | 接口 | 说明 |
|---|---|---|---|---|
| 温湿度 | AHT20 | ~8 元 | I²C 0x38 | 够用 |
| 温湿度（更准） | SHT30 | ~20 元 | I²C 0x44 | ±2%RH |
| 气压 | BMP280 | ~6 元 | I²C 0x76 | 可选 |
| 光照 | BH1750 | ~6 元 | I²C 0x23 | 自动调背光 |

I²C 总线 = GPIO47/48（与 QMI8658 共用），四线并联即可，板上已有 4.7 kΩ 上拉。

---

## 3. 「身后有人看屏幕」的两条技术路线

### 路线一：板上跑人脸检测（ESP-DL / ESP-WHO）
- ESP32-S3 + 8 MB PSRAM 可跑轻量人脸检测模型，QVGA 约 5–10 fps
- **只能判"有脸"，判不了"在看"**；阈值需现场调
- 工期 1–2 天，模型量化与调参存在不确定性
- 优点：完全独立，不依赖 PC

### 路线二：PC 侧推理（**推荐**）
```
板子（已有 8080 MJPEG 推流） → PC（Python + MediaPipe/OpenCV）
        ↓                                    ↓
   屏幕变红告警  ←──────── HTTP 指令 ────────┘
```
- 判据：画面中出现人脸且持续 > 1.5 s → 告警
- 可扩展：人脸朝向估计、人脸计数、陌生人识别
- 工期约 0.5 天，精度高一个数量级
- 取舍：PC 需常开 —— 但使用场景本就是"在电脑前"，代价为零

### 关键设计：摄像头朝身后
镜头朝自己背后装 → 自己的脸永远不在画面里 → **"画面出现人脸" ≈ "身后有人"**，误报天然极低。
这个几何关系是本方案成立的前提。

## 4. 复用方案 A 的部分

| 组件 | 复用方式 |
|---|---|
| 屏幕渲染框架 | 同一套"页面"机制，加一页"仪表盘" |
| 熄屏 / 唤醒 | 直接沿用（IMU 敲击唤醒） |
| BLE 通道 | 复用同一 GATT 服务，新增 `S` 指令回传传感器读数 |
| 电源管理 | 桌面场景可长期插电，策略可放宽 |

## 5. 待办（启动时从这里接手）

1. AHT20 驱动 + I²C 扫描（确认不与 0x6A 的 IMU 冲突）
2. NTP + 天气拉取（带缓存，断网显示上次结果 + 时间戳）
3. 仪表盘页面布局（时间大字 / 日期 / 温湿度 / 天气图标）
4. PC 侧 `watch.py`：拉流 → MediaPipe 人脸检测 → 告警回调
5. 告警联动：屏幕红边闪烁 + PC 弹窗（可选音量渐降）

## 6. 风险

| 风险 | 对策 |
|---|---|
| 天气 API 限额/失效 | 换源 + 本地缓存 + 显示数据时间 |
| 人脸误报（照片、海报） | 要求"连续多帧 + 人脸尺寸下限" |
| PC 侧常驻程序被关 | 做成托盘程序 + 开机自启 |
| 屏幕长期常亮老化 | 亮度降级 + 夜间自动熄屏 |
