# 票据屏固件（firmware/notepad）M1 + M2

ESP32-S3-LCD-2 的第二个固件：**手机通过蓝牙把票据/便签文本推到屏幕上**，设备存下来随时看；
一段时间没人管就熄屏省电，**敲一下板子亮起来**。
Wi-Fi 只用于 OTA 升级，连不上也不影响 BLE 主功能。

## 硬件与依赖

| 项 | 值 |
|---|---|
| 屏幕 | ST7789T3 320×240，SPI：SCLK 39 / MOSI 38 / DC 42 / CS 45 / BL 1 |
| IMU | QMI8658A（I2C：SDA 48 / SCL 47，地址 0x6A），加速度计 + 陀螺仪：敲击唤醒 + 甩动翻页 |
| 存储 | FFat（`ffat` 分区，10 MB） |
| 蓝牙 | NimBLE-Arduino 1.4.x（arduino-esp32 2.0.17 / IDF 4.4） |
| 图形 | GFX Library for Arduino 1.4.9（**不能升 1.5+**，它要 core 3.x） |
| 中文字库 | `data/cjk16.bin` 295 KB（小字）+ `data/cjk24.bin` 589 KB（大字），各 7540 字 |

## BLE 协议

设备名 `ESP32-NOTE`，Nordic UART Service：

| 角色 | UUID | 属性 |
|---|---|---|
| Service | `6E400001-B5A3-F393-E0A9-E50E24DCCA9E` | – |
| RX（手机→设备） | `6E400002-B5A3-F393-E0A9-E50E24DCCA9E` | Write / WriteNoRsp |
| TX（设备→手机） | `6E400003-B5A3-F393-E0A9-E50E24DCCA9E` | Notify |

一行一条指令，`\n` 结尾，UTF-8；回执通过 TX notify 返回。

| 指令 | 说明 | 回执 |
|---|---|---|
| `V` | 查版本 | `OK V 0.2.0` |
| `T 标题\|行1\|行2\|…` | 新增条目（`\|` 分隔，最多 12 行） | `OK T <id> <总数>` |
| `L` | 列出条目 | `OK L <总数>` + 每条 `ITEM <id> <标题>` |
| `P <id>` | 显示指定条目 | `OK P <第几条>` |
| `N` / `R` | 下一条 / 上一条 | `OK P <第几条>` |
| `D <id>` | 删除 | `OK D` / `ERR NOTFOUND` |
| `C` | 清空 | `OK C` |
| `B <0-100>` | 背光亮度 | `OK B <pct>` |
| `S <0\|1>` | 手动熄屏 / 点亮 | `OK S <0\|1>` |
| `O <秒>` | 自动熄屏超时，`0` = 常亮 | `OK O <秒>` |
| `A` | 读加速度（g） | `OK A <x> <y> <z>` / `ERR IMU` |
| `G` | 读加速度 + 陀螺仪（g / °/s） | `OK G <ax> <ay> <az> \| <gx> <gy> <gz>` / `ERR IMU` |
| `K <1\|-1\|t>` | 甩动翻页方向：`1`/`-1` 直接设定，`t` 取反，不带参数=查询；**存 NVS，重启后仍生效** | `OK K <1\|-1>` |
| `Q` | 甩动统计（标定用） | `OK Q <次数> <最近角度> <轴> \| now <dps> peak <dps> \| <页码> \| k<n>` |
| `I <w> <h>` | 开始收图（w≤320、h≤212） | `OK I START WxH` |
| `A <base64>` | 送一段 base64 编码的 RLE（可多次，单行≤380 字符且为 4 的倍数） | `OK A <累计字节>` |
| `E` | 结束并上屏 | `OK E <id> <rle字节> <位图FNV32>` / `ERR DECODE` |
| `Z` | 放弃本次收图 | `OK Z` |
| 其它 | – | `ERR UNKNOWN` |

示例：

```text
T 高铁票 G106|2026-11-02 08:25 开|济南西 → 北京南|二等座 12车 12A号|票价 314.5 元
```

## M2：熄屏与敲击唤醒

- 上电默认 60 秒无交互熄屏（`O 60`），`O 0` 可关掉自动熄屏
- 熄屏时只关背光，屏幕内容保留；任何 BLE 指令、翻页都会自动点亮
- 熄屏期间每 25 ms 读一次 QMI8658 加速度，相邻采样三轴变化量之和 > 0.75 g 且距上次敲击 > 500 ms 判定为"敲一下"
- **IMU 不可用时不熄屏**（否则唤不醒，只能复位）
- 没有用 IMU 的 INT1 引脚：`GPIO3 = LCD_TE = IMU_INT1`，中断走轮询代替，省掉引脚冲突
- 敲击阈值 0.75 g 是估值，误亮就调大 `src/power.cpp` 的 `TAP_THRESHOLD`

## 甩一下翻页（v0.3.0）

- 陀螺仪 **±2048 dps** / 125 Hz，25 ms 一采（原来 ±512 dps，手甩就削顶丢角度）；角速度超过 70 dps 起手，回落到 25 dps 以下（或手势超过 1.5 秒强制结算）且累计转角 ≥ 30° 判定为一次甩动；快速一挥转角不够时，峰值 ≥ 600 dps 且 ≥ 15° 也认
- 累计角度按 `角速度 × 0.025` 积分，取三轴里转角最大的那个定方向
- 往右甩 → 下一条，往左甩 → 上一条；**方向反了把 `src/power.cpp` 的 `SWIPE_DIR_SIGN` 改成 `-1`**
- 熄屏时甩动只负责唤醒，不翻页；只有 1 条消息时甩动不动作
- 调试：发 `Q` 看 `次数 / 最近角度 / 轴`，后面还带 `now`（当前角速度）和 `peak`（上电以来峰值）——**甩的时候 peak 上不去就说明传感器没看见动作**，跟阈值无关

```text
[->] Q
[<-] OK Q 4 63.2 y | now 3 peak 412 | 2/2 | k1   # 甩了 4 次，63.2°绕 y 轴；第 2 条/共 3 条；方向符号 1
```


## 甩动标定（v0.3.0 修订）

方向"拧紧/拧松"式判断，不绕术语：

| 动作 | 角度符号 | `sn=-1`（默认）下的效果 |
|---|---|---|
| 顺时针 / 拧紧 | 负 | **下一条** |
| 逆时针 / 拧松 | 正 | **上一条** |

- 量程 ±2048 dps（`LSB_PER_DPS 16.4`）：±512 会被甩爆削顶，角度只记一半
- 角度按**实测 dt** 积分（`loop()` 里有 BLE/刷屏，真实周期 40–60 ms）
- 判定：转够 30° 就算；不足 30° 但峰值 ≥600 dps 且转 ≥15° 也算（"用力一甩"兜底）；冷却 450 ms
- 观察串口：`[PWR] 起手 g=(...) a=(...)`、`[PWR] 甩动 轴=z 转=75.5度 峰值=203 -> 下一条`、`[PWR] 甩动不足 15.9度 峰值175 -> 忽略`
- 方向反了：App 点「翻转方向」（发 `K t`）或串口发 `K t`/`K -1`

## 串口也能下指令（调试用）

手机连着 BLE 时 NUS 被占用、PC 端 `ble_test.py` 扫不到设备，此时直接把指令打到 COM16（115200）：


## 传图片上屏（v0.3.1）

手机/PC 把一张图压成 1-bit 位图再送过来，屏幕按 320×212 显示（底部 28px 留给页脚）。

**格式**

- 位图：行按字节对齐（`stride = (w+7)/8`），每字节 **MSB 是左边像素**，`1=白`、`0=黑`
- RLE：成对 `[count u8][value u8]`，`value` 只能是 `0x00`/`0xFF`，`count` 1..255
- 接收缓冲 `IMG_BUF_MAX` 16 KB；解码后位图放 PSRAM，再落 FFat

**存哪**

- 图片文件 `/i<id>.rle`（4 字节头 = w,h 小端），索引 `/imgs.txt`
- 最多 3 张，满了挤掉最旧；`C` 清空会一起删掉；重启后 `load_images()` 重新加载

**为什么回执先发后落盘**

写 FFat 时 flash 被占用，BLE 栈会卡住；如果先写盘再 `ble_send()`，这条 `OK E` 会丢。
所以 `notes_add_img_rle(..., persist=false)` 先把条目挂到内存、立刻回执，再 `notes_save()`。

**校验**

`E` 回执里的 FNV32 是**解码后的位图**哈希。PC 端用同样算法算一遍，两边一致就说明一个字节都没错。

## 关键实现点

- **BLE 写入是分片的**：MTU 517 下一条长指令会分多包，固件按 `\n` 累积重组后再执行
- **指令在 loop() 里执行**：BLE 回调只把整行塞进 FreeRTOS 队列，避免在 BLE 任务里做 SPI 刷屏和 FAT 写入
- **两套字号共用一套记录格式**：单字记录长度 = `8 + ceil(w/8) * h`（16px 为 40 B，24px 为 80 B），按码点二分查找
- **`GPIO0 = LCD_RST = BOOT`**：软件里不能把 GPIO0 拉低，否则会进下载模式
- 条目上限 8 条，超出挤掉最旧的；单行 100 B（约 33 汉字），标题 64 B

## 已知限制

- 每次指令全屏重绘（约 40 ms，肉眼看不出，但都不是局部刷新）
- 图片/截图负载（`I` 指令 + 1-bit RLE）尚未实现（M3）
- BLE 无配对加密，同频段任何人都能写——计划加 6 位 PIN 握手
- 敲击阈值 0.75 g 是估的，真机上如果桌子轻微震动就误亮，把 `power.cpp` 的 `TAP_THRESHOLD` 调大
- 甩动灵敏度也是估值（80 dps 起手 / 30° 判定）；甩半天不翻页先看 `Q` 的 `peak`：`peak` 上不去是传感器/摆放问题，`peak` 很高但不翻页才是阈值问题
- `V` 版本号已到 0.3.0；`/status.json` 里的 `rx` 是收到的指令计数，用来判断"手机点的到底有没有到设备"
